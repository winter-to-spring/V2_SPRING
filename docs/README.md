# Documentation Map

- `adr/` - architectural decisions and commitments
- `architecture/` - system structure and phased build plans
- `charter/` - product intent, boundaries, and non-goals
- `specs/` - implementation-facing specs such as the tracer bullet
- `verification/` - how founder/operator verification works
- `runbooks/` - operational procedures

Archived V1 materials live under [`archive/v1/`](../archive/v1/).

## Issue Prefix Convention

New GitHub issues should use one of these prefixes in the title:

- `[코어]`
- `[UI]`
- `[운영]`
- `[인프라]`
- `[문서]`
- `[검증]`

This keeps execution slices easy to scan and makes handoff between agents less ambiguous.
